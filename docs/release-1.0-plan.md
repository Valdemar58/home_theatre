# План релиза home_theater 1.0

Подтверждён владельцем 19 ноября 2026 года после grilling Q1–Q41.
Этот документ определяет состав 1.0; старый
`development-roadmap.md` сохраняется как история, а не текущий статус работ.
Статусы задач ведутся в GitHub Issues/Projects; этот файл хранит договорённости.

## Продукт и обязательная приёмка

Личный эксперимент: один серверный продукт с опциональными компонентами,
общим UI веба и desktop. Сервер: Ubuntu Server 24.04 LTS x86_64 + Compose.
Windows desktop — stable после приёмки; Arch — preview с явными ограничениями.
Текущий серверный медиапуть сохраняется и проверяется на регрессии.

Обязательная цепочка: установка → аккаунт и доступ → вход/привязка desktop →
поиск torrent/magnet → выбор серий → локальная загрузка (включая команду из веба)
→ подготовка → одиночный и совместный просмотр в браузере → ручные/автоматические
переходы, перерывы, смена хоста → прогресс и история → обновление без потери данных
и привязки. Смена хоста использует ту же версию файла и буфер по принятой
спецификации совместного просмотра.

пути. Каждая веха заканчивается пригодным к проверке кандидатом с описанными
ограничениями. Успех CI не равен пользовательской приёмке.

## Оценки и участие владельца

| Веха | Активные рабочие дни, предварительно | Участие владельца |
|---|---:|---|
| R1: репозиторий и исходная версия | 2–3 | Принять исходные проблемы и конкретные переносимые ограничения |
| R2: аккаунты | 2–4 | Проверить личный прогресс, вход, восстановление, приглашение |
| R3: сервер | 3–5 | Чистый VPS/DNS, самостоятельная установка, окно обслуживания |
| R4: флаги | 2–4 | Проверить управление и аварийное отключение |
| R5: desktop | 3–5 | Установка без подсказок, профили, обновление |
| R6: приёмка | 3–5 | Реальный просмотр с другом через разные сети |
| R7: выпуск | 1–2 | Принять стабильный выпуск и обновление боевого сервера |

Итого 16–28 активных дней, с резервом примерно 20–35. Не календарное обещание;
ожидание доступа, оборудования и пользовательской приёмки отдельно. После R1
пересчитать оценки по установленным фактам. R2 → R3 → R4 → R5 → R6 → R7;
подготовку независимых задач можно совмещать без пропуска проверок.

R3 проверяет установку до выпуска 1.0 на отдельном чистом окружении, без переноса
рабочей системы владельца. Для установщика и локальной проверки подходит чистая
VM Ubuntu 24.04; публичный HTTPS и подключение из другой сети дополнительно
проверяются на доступном извне сервере. Перенос рабочей системы владельца и её
данных на постоянный VPS относится к R7 после приёмки конкретного кандидата.

## GitHub и процесс (Q1–Q19)

- Публичный монорепозиторий, отдельные сборки сервера и desktop, общий номер
  продукта. Собственная open-source лицензия пока не назначается; лицензии
  включённых зависимостей проверяются перед распространением сборок.
- Короткий русский README: назначение, статус, ссылки. Wiki/Discussions не нужны.
- Issues: инкременты и баги. Milestones: выпуски. Один Project:
  «Запланировано / Готово к работе / В работе / На проверке / Принято».
- `main` защищён, короткие `codex/*`, PR, нет force-push/удаления main.
  Агент сливает согласованные задачи после обязательных проверок и ревью;
  второй человек для каждого PR не требуется. Слияние не означает принятие
  пользовательского результата. Принятие — владелец, стабильный выпуск и
  обновление боевого сервера — по его решению.
- На PR: секреты, типы, тесты, сборка затронутых компонентов; БД/API — PostgreSQL.
  На main — проверки. Кандидат — явный запуск, полная упаковка и сквозной прогон.
  Пересобранные финальные пакеты проверяются заново.
- GitHub Releases: desktop/контрольные суммы/метаданные обновлений. GHCR: сервер.
  Публикация не обновляет VPS автоматически. GitHub не хранит доступ к VPS.
- GitHub-hosted runners, внешние PR — после одобрения, без секретов/публикации.
  Публикация из доверенной ветки отдельными правами. Actions закреплены по SHA.
- Dependabot: security updates, еженедельные группы обычных обновлений,
  несовместимые major отдельно, без безусловного auto-merge.
- Логи/отчёты 14 дней, временные пакеты Actions 7 дней. Стабильные релизы и образы
  сохраняются; опубликованные кандидаты удаляются только явно.
- Бесплатно по умолчанию, платные расходы согласуются отдельно.

## Эксплуатационные договорённости (Q20–Q40)

- Регистрация без одобрения открывает только состояние ожидания. Одноразовое
  приглашение с TTL выдаёт доступ после завершения регистрации. Логин/пароль,
  ник отдельно; обязательной почты нет. Владелец восстанавливает вход командой
  на VPS, администратор создаёт одноразовую ссылку участнику.
- Существующий admin становится личным аккаунтом с сохранением ID. Администратор
  — роль. Миграция проверяется на копии; внешние пароли не копируются.
- Базовая модульность: конфигурация, возможности, версии, диагностика/деградация.
  Полный менеджер скачиваемых расширений в 1.0 не входит.
- Обновление назначает версию и окно. Уведомления по умолчанию за 15 и 5 минут.
  В окне запрещаются новые сеансы, активные синхронно ставятся на паузу с
  сохранением позиции; новые серверные задачи не принимаются, выполняющиеся
  безопасно останавливаются/завершаются. Затем успешный бэкап и обновление.
  Если безопасная остановка не удалась в окне, обновление отменяется с причиной.
  Независимые локальные загрузки desktop продолжаются. После рестарта
  восстанавливается состояние; бесшовность не обещается.
- Бэкап БД, конфигурации и необходимых секретов с ограничением доступа; медиа
  не дублируется. Перед обновлением обязателен; ручной доступен. Ежедневная
  ротация реализована, выключена по умолчанию. Исходная настройка: 7 ежедневных
  копий и последняя предобновительная. Локальные копии не защищают от потери VPS.
- Прямое подключение desktop → зритель; TURN отложен. Реальные сети проверяем;
  невозможность прямого подключения объясняем, не выдаём за успешный просмотр.
- Desktop: раздельные профили серверов/авторизации/привязок. Разрешения раздачи
  между серверами не переносятся автоматически. Канал обновления отдельно от
  профиля. Обновление по кнопке не прерывает активный просмотр самопроизвольно.
- Поддержка соседних версий и rolling deployment отложены. Проверка протокола и
  возможностей обязательна: несовместимый desktop требует обновления без потери
  данных; обновлятор работает независимо от доступности серверного API.
- Unleash OSS опционален. Решения принимает сервер; клиент получает нужные
  значения. При сбое — последнее корректное состояние, при его отсутствии —
  безопасные defaults (эксперименты выключены). Есть локальное принудительное
  отключение. Выключение через недоступную панель не гарантируется.
- Обычный флаг фиксируется на сеанс. Аварийное действие сохраняет прогресс и
  синхронно останавливает проблемную операцию; возврат к старой обработке только
  при явно реализованной и проверенной возможности. Флаг не откатывает БД.
- Уточнение R4 от 20.11.2026: первым сценарием выбраны постоянные выключатели
  ИИ (весь ИИ / общие анализы / персональные функции / обработка медиа).
  Это эксплуатационные разрешения: они проверяются перед каждым обращением к
  провайдеру, включая задания после ожидания в очереди, и не фиксируются на
  сеанс просмотра. Уже отправленный запрос может завершиться и оплачиваться.
  Отключение не скрывает сохранённые результаты и не останавливает видео.
  Лимиты и резервирование бюджета — отдельный инкремент. Фиксация на сеанс
  остаётся требованием к будущим экспериментам с двумя реализациями;
  такие эксперименты этой проверкой не считаются проверенными.
- Временный флаг сразу получает задачу удаления и релиз пересмотра. Удаление
  отдельным PR после приёмки, реальных проверок, устранения блокеров и завершения
  миграций/старых зависимых задач. Срок лишь напоминает; постоянный аварийный
  выключатель может остаться без старой реализации.
- Обязательный сценарий и новые регрессии блокируют релиз. Старые неисправности
  дополнительных функций переносятся только по конкретному решению владельца.

## Следующие вехи, не блокирующие 1.0

Standalone, замена arr, полноценные расширения, распределённая координация и
rolling updates/k8s, поддержка соседних версий, TURN, пересмотр ИИ/кэшей/лимитов.

## Критерий выпуска

Все обязательные задачи приняты; CI и сквозная проверка зелёные; установка,
обновление и восстановление проверены на конкретных артефактах. Ограничения
перечислены явно. Arch остаётся preview. Нет утверждения «готово» на основании
одной сборки, макета или существования кода.
