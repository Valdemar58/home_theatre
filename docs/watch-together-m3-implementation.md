# М3: исполнение плана сеанса

Дата: 12 ноября 2026. Продолжение M2 на существующем медиабэкенде.

## Поведение

- При запуске запланированной встречи в комнату копируется неизменяемый план. Курсор — блок и индекс выбранной серии, а не арифметическое «номер + 1».
- Конец серии запускает общий серверный отсчёт 10 секунд. Между тайтлами применяется перерыв из завершённого блока. Нулевой перерыв допускает немедленный переход; после последнего блока перерыва нет.
- Управляющий может отменить автопереход, включить/отключить автовоспроизведение и запустить следующий пункт сейчас. Отключение не останавливает ход часов: при истёкшем сроке включение запускает переход на ближайшем серверном тике. Пока выключено, видна надпись «Ожидание организатора».
- Переход не требует подтверждения готовности. Комната ждёт технической загрузки у подключённых зрителей. Кнопка «Продолжить без ожидающих» исключает отстающего из блокирующих до сообщения о его возвращении. Автоисключения через 90 секунд для планового просмотра нет.
- Невышедший или неизвестный следующий эпизод не пропускается: запуск блокируется, автовоспроизведение выключается, доступен явный повтор после исправления метаданных/выхода серии.
- Плеер переключает тайтл и серию внутри сохраняемой fullscreen-обёртки. Обычный выбор произвольной серии во время плана отклоняется; порядок начатого плана не переписывается.
- После последней серии состояние — «Сеанс завершён», встреча переносится в историю со статусом done. Это завершение исполнения, не доказательство просмотра всех серий каждым участником. Новая модель результата встреч и персональные циклы относятся к M4.

## Механика и ограничения

Состояние хранится в существующем `watch_rooms.state`: snapshot блоков, курсор, phase, deadline, autoplay, revision и heartbeatAt. Новая миграция не требуется. Следующая серия выбирается только из snapshot; клиентские опоздавшие команды и отчёты проверяются по revision, тайтлу и серии. Команды и тики сериализуются транзакцией с блокировкой строки комнаты. Уведомление о конце принимается от вошедшего зрителя только рядом с концом общей позиции; длительность сообщается медиаплеером, не является серверным доказательством просмотра.

Планировщик исполняет сроки раз в секунду. Общие EventEmitter/presence живут в process-global runtime, потому что Next собирает фоновые задачи и API отдельными модулями. SSE дополнительно сверяет снимок раз в секунду. Это сохраняет текущую однопроцессную архитектуру; распределённая presence/pubsub для нескольких реплик не реализована.

Потеря SSE ставит локальное видео на паузу. Сервер сохраняет координационный heartbeat; разрыв работы планировщика более 15 секунд выключает автоматические переходы и возвращает общую позицию к последнему heartbeat. При таком восстановлении управление продолжением остаётся у человека. Само наличие файла и запуск декодера по-прежнему зависят от существующего медиабэкенда и браузера.

Личный прогресс записывается существующим медиаплеером. Настройка M2 «не учитывать OP/ED» влияет только на оценку расписания, не меняет фактический конец файла или критерий зачёта серии.

## Проверки

- TypeScript и production Docker/Next.js build.
- 25 тестов в четырёх профильных файлах на SQLite; 20 интеграционных тестов в трёх файлах на отдельной PostgreSQL 17 (последовательно).
- Сценарии: непоследовательные серии, два тайтла, точная граница перерыва, финал без последнего перерыва, отмена/возврат autoplay, устаревшие события, права, перенесённый релиз, barrier только для подключённых, продолжение без отстающего, восстановление после остановки координации.
- Браузерная проверка использует явно тестовые состояния в однопользовательской комнате 4. Для выбранных тайтлов нет подготовленных файлов: проверки UI/синхронизации команд не выдаются за сквозной медиапрогон. Проверка двух физических устройств с реальным потоком остаётся отдельной проверкой.
- Браузер выявил рассогласование фонового EventEmitter с API; введены process-global runtime и периодическая сверка SSE.

Независимый Impeccable finish review: **ship в проверенном объёме next/break/complete**. Исправлены оба замечания: срочная отмена теперь всегда видна на узком плеере; глобальные горячие клавиши больше не перехватывают Space у кнопок. Space и Enter проверены через браузер. Перерыв и завершение проверены на 1440 и 390; основной снимок next проверен также в обычном пользовательском viewport. Финальные next-снимки: `.impeccable/review/m3/next-mobile-final.png`, `next-desktop-final.png`; финал: `complete-mobile.png`, `complete-desktop.png`.

Серверный переход реально доставлен в браузер без reload; отменённый переход остался в ожидании после 0:00, а включение autoplay после срока перевело плеер на следующий пункт. Смена тайтла через кнопку плеера сохранила fullscreen (нативный снимок `fullscreen-title-transition.png`). Тестовые UI-состояния создавались напрямую и имели увеличенный срок для снимков; обработка сигнала конца серии и десятисекундный срок проверены серверными тестами с управляемыми часами, не воспроизведением файла в браузере.

Тестовый просмотр закончен через UI, искусственная встреча помечена cancelled в комнате 4; рабочая комната 3 не менялась. Временная PostgreSQL удалена после тестов. Существующие живые комнаты без snapshot M3 автоматически не переинтерпретируются: новая логика применяется к запущенным этой версией плановым сеансам.
