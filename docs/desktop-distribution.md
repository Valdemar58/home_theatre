# Desktop: упаковка, установка и обновления

Дата решения: 2026-11-17. Рабочее название: home_theater.
Целевые системы первого выпуска: Windows и Arch Linux, x86-64.

## Принятое направление

Electron с существующим веб-интерфейсом. Chromium одинаков на обеих платформах;
это уменьшает расхождения плеера, ценой размера пакета и потребления памяти.
Локальный медиапроцесс отделяется от удалённых страниц. Node integration выключен,
renderer работает в sandbox; произвольных команд, файловых путей и IPC из страницы нет.
Версии инструментов закреплены в `apps/desktop/package.json` и lockfile.

| ОС | Распространение | Установка | Первый способ обновления |
|---|---|---|---|
| Windows | NSIS `.exe` | Для текущего пользователя, без обязательных прав администратора | Закрыть хост после завершения задач, запустить новый установщик поверх предыдущего |
| Arch Linux | `.AppImage` | Скачать в постоянную папку, дать право исполнения, запустить | Завершить хост, заменить AppImage новым, снова разрешить исполнение |

Пример Arch: `chmod +x home_theater-<version>-linux-x86_64.AppImage`.
AppImage требует проверки на актуальном Arch с Wayland и X11; наличие FUSE нельзя
считать гарантированным. Способ запуска без FUSE и необходимые системные зависимости
должны быть проверены на чистой машине перед выдачей пользовательской инструкции.
Не предлагать `--no-sandbox` как обход проблем установки.

AUR `-bin` — возможный последующий канал, не обязательная зависимость первого выпуска.
При его добавлении обновления выполняет пакетный менеджер; приложение не заменяет
установленные им файлы. Flatpak и дополнительные архитектуры пока не входят в базовую матрицу.

## Данные и удаление

Установочная папка/AppImage не содержит библиотеку. Настройки и реестр локальных файлов
живут в каталоге данных пользователя; расположение медиабиблиотеки выбирается отдельно.
Подключение файла не перемещает и не удаляет оригинал. Удаление приложения и обновление
не должны удалять исходные серии. Подготовленные производные файлы учитываются отдельно.
Автозапуск и фоновая раздача включаются только пользователем.

## Публикация и автообновление

Первый канал — версия на HTTPS-странице релизов с пакетами и SHA-256, журналом изменений
и указанием поддержанных платформ. Конкретный endpoint ещё не назначен; публичных
артефактов и работающего update feed сейчас нет. Сборки выполняются с `--publish never`.
Checksum помогает обнаружить повреждение, но не заменяет подпись издателя.

Публичный Windows-релиз требует Authenticode. Ранние неподписанные внутренние сборки
должны быть явно обозначены; отсутствие предупреждений SmartScreen не обещается.
Для автоматических обновлений нужны подписанные метаданные, встроенный ключ проверки,
защита от отката версии и проверка целостности пакета. До настройки и испытания этого
канала используются ручные обновления. Наличие electron-builder само по себе не
означает, что автообновление реализовано.

Будущий updater может скачать обновление фоном, но применение — только после остановки
раздачи/подготовки с понятным уведомлением. Нельзя молча завершать сеанс или перезапускать
хост. Каналы stable/preview раздельны, переход на preview явный. Обновление веб-интерфейса
не должно менять активный протокол desktop без согласования версии; несовместимый хост
получает требование обновиться, а не ложную готовность.

## Границы М5

М5: регистрация устройства, отзыв, heartbeat, подключение файлов, проверка их полной
SHA-256, локальная подготовка, разрешение конкретному тайтлу и комнате, inventory хостов.
Полный хэш исходника не доказывает идентичность таймлайна подготовленной версии.
М6: реальная передача в браузер через разные сети, включая диагностику NAT/relay/кодеков.
М7: автоматическая смена хоста. Не выдавать локальную готовность за проверенную
доступность потока удалённому зрителю.

## Состояние alpha.1

Реализованы браузерное подтверждение устройства, отзыв, heartbeat, локальная библиотека,
полный SHA-256 исходника, подготовка MP4 через встроенный FFmpeg и разрешения на тайтл
для конкретной комнаты. В комнате отображаются разрешённые серии ближайшего сеанса.
Настройки → Мои устройства открывает управление привязками. Сервер 5056 обновлён.

Собраны Windows NSIS и Linux AppImage. Windows-пакет установлен в отдельную тестовую
папку и запущен; тесты библиотеки и реального транскодирования прошли на Windows/Linux.
AppImage runtime и встроенные медиабинарники проверены в WSL. Это не заменяет приёмку
GUI на чистом Arch с Wayland/X11: она остаётся открытой, как и проверка обновления между
двумя разными выпусками. Подробная матрица — [отчёт М5](watch-together-m5-implementation.md).

Первый выпуск подключает существующие локальные файлы. Подготовка использует первую
видеодорожку и первую аудиодорожку; субтитры и выбор дорожек для потока требуют следующего
этапа. Оригиналы сохраняются. Установленная сборка требует HTTPS-сервер; разработческий
запуск допускает HTTP loopback. Передача подготовленного видео через интернет ещё не включена.
