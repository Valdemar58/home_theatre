## Подтверждённый исходный сценарий

Проверка изолирована от пользовательской БД: контейнер на 5057, SQLite с двумя
синтетическими аккаунтами, отдельный desktop-профиль, минутное синтетическое видео.
Login-провайдер и индексатор тестовые; BitTorrent, FFmpeg, WebRTC, сервер API,
Electron и Chromium настоящие. Эти границы не заменяют внешнюю авторизацию,
реальный индексатор, NAT/VPN или проверку с другом из другой сети.

1. Вход внутри desktop и привязка устройства; повторное действие возвращает тот же
   ID и alreadyLinked=true. После перезапуска профиль сохраняет привязку и файлы.
2. Из авторизованного веб-контекста: поиск → выбор серий 1 и 3 → команда desktop →
   скачивание по 30 858 537 байт → реальная FFmpeg-подготовка. Серия 2 не загружена.
   Первый прогон сделан до обновления Next; повторный поиск/доставка команд на
   новом коде проверены. Повторное добавление того же torrent правильно отклонено.
3. Комната с двумя аккаунтами, разрешение хостинга тайтла комнате, прямой поток
   в desktop и отдельный браузер: readyState=4, 1920×1080. Зрителю desktop не нужен.
4. Общая пауза: оба плеера остановились; пример локального замера 35,959/36,232 с.
   Это отдельный замер, не гарантия точности в интернете.
5. Кнопка следующей серии внутри плеера перевела обоих с 1 на 3, затем продолжилось
   воспроизведение без повторного подтверждения. Доступность определялась готовыми файлами.
6. Через интерфейс редактора выбран план: тайтл 42 — серии 1,3; затем тайтл 43 —
   серия 1; перерыв 1 минута. Сохранение, повторное открытие, перемещение тайтла
   вверх/вниз и изменение настройки OP/ED сохранились. Расчёт: 2+1+1=4 минуты;
   последний перерыв не добавляется к окончанию, короткие серии не сокращаются.
7. Запланированный сеанс создал комнату штатным фоновым обработчиком. Оба зрителя
   подключились. После натурального окончания первой серии — 10-секундная плашка,
   автоматический переход к серии 3. Затем синхронный минутный перерыв.
8. Автовоспроизведение выключено checkbox в плеере. По истечении deadline комната
   осталась в break, на обоих клиентах 0:00 и «Ожидание организатора». Включение
   checkbox запустило второй тайтл на обоих клиентах без отдельного «Продолжить».

9. Натуральное завершение второго тайтла перевело сеанс в done. Результат встречи:
   42 → [1,3], 43 → [1], участники [3,4]. Личный цикл сохранил серии [1,3].
10. Через API исправления истории выполнены preview и отметка пропущенной встречи
   как офлайн-просмотренной: серия 2 добавилась обоим участникам. Последующая
   корректировка результата отменила только организаторскую отметку: личные
   онлайн-события серий 1 и 3 сохранились; в журнале остались обе редакции.

Для второго тайтла заранее подключена подготовленная синтетическая копия;
его отдельная раздача не скачивалась. Torrent/magnet, повторная доставка команд,
библиотека и транспорт дополнительно покрыты 15 desktop-тестами: 15 passed, 0 skipped.
Скриншоты сохранены локально в docs/screenshots/r14-baseline (игнорируются Git).

## Неисправности и ограничения перед 1.0

| Пункт | Доказательство | Дальнейшая работа |
|---|---|---|
| Backup-check ожидает две миграции | На PostgreSQL 17 воспроизведено 12 !== 2 после успешного восстановления данных | [#37](https://github.com/Valdemar58/home_theatre/issues/37), R3.3 |
| Остались advisories ip/glob/minimatch | GitHub alerts 12–15: 1 high, 3 medium; Next/Vite из открытых alerts исчезли | [#38](https://github.com/Valdemar58/home_theatre/issues/38), разбор до 1.0 |
| Серверный медиапуть не пройден живым прогоном | Его Prowlarr/Sonarr/qBittorrent/TorrServer/stream-router выключены | [#39](https://github.com/Valdemar58/home_theatre/issues/39), R3.2/R6 |
| OCR/внешние субтитры/книги/LLM | Соответствующие дополнительные контейнеры выключены; реальные внешние API не подтверждены | Поимённая проверка в #39; перенос конкретного ограничения требует решения владельца |
| Прямое соединение через разные сети, смена хоста при реальном обрыве | Этот прогон использует один ПК/loopback; M7-регрессии не равны реальному интернету | R6; TURN не входит в 1.0 |
| Arch GUI и обновление приложения | Нет устройства для полноценного прогона | Arch preview, Windows stable после R5–R7 |

После переноса папок все 11 ранее автоматически запускавшихся контейнеров работают;
сервисы с healthcheck здоровы, /api/health/database и /login на 5056 возвращают 200.
Bind mounts продолжают работать через junction на D:. Production-образ и данные
не обновлялись тестовой сборкой. Остановленные опциональные сервисы не объявлены
поломанными только по отсутствию процесса.

## Как принять

Достаточно написать «R1 принято» либо перечислить принятые этапы и замечания.
Агент обновит Project, последнюю строку чек-листов и закроет принятые Issues.
Можно самому перевести карточки в «Принято» и сообщить агенту; автоматического
закрытия Issue от этого действия нет. Отдельно проставлять все галочки не нужно.

Приёмка R1 означает согласие с устройством работы и достоверностью исходного
реестра. Она не разрешает автоматически переносить неисправности за пределы 1.0
и не означает разрешения стабильной публикации или обновления рабочего сервера.

## Сборка и запуск

Основной Dockerfile успешно собран после повторного запуска (первый упал на
I/O error при распаковке x265). Полный функциональный прогон нового кода выполнен
на образе r14-runtime с прежним системным слоем. После окончания сеанса тестовый
контейнер заменён полной сборкой r14-baseline-20261119 с той же тестовой БД;
запуск дал HTTP 200 и Next 16.4.5. Повторный прямой playback в двух клиентах
прошёл: readyState=4, 1920×1080, paused=false. История встречи и привязка после
замены контейнера сохранились. Vite 8.3.8 присутствует в build-stage и исключён
из production зависимостей как dev-инструмент.
