# Единый интерфейс desktop и веба

18 ноября 2026. Desktop 0.5.0-rc.1.

## Реализовано

Основное окно привязанного desktop открывает существующий общий фронтенд. Каталог, календарь, списки, комнаты, плеер и загрузки используют одни React-компоненты с вебом. Локальный движок продолжает работать в изолированном окне без доступа сайта к Electron IPC. Привязка и расширенные локальные инструменты доступны из меню приложения. При недоступном сервере остаётся локальная панель; автономный общий интерфейс пока не поставляется.

В карточке тайтла появился переход «Скачать на устройство». В плеере тот же выбор доступен в раскрываемом блоке. Раздачи ищутся через сервер; torrent и magnet сохраняются как задание выбранного собственного устройства. Онлайн-устройство получает метаданные, после чего пользователь выбирает серии слотами; неоднозначные номера уточняются в раскрываемом списке файлов. На выключенный компьютер можно отправить выбранные номера серий из известного состава тайтла. После подключения автоматический запуск допускается только при однозначном соответствии номеров файлам. Иначе задача останавливается для уточнения.

Общая страница загрузок показывает последнее состояние устройства, серии и прогресс с весами 80% скачивание / 20% подготовка. Есть пауза, возобновление и отмена незавершённой загрузки. Готовая серия открывает существующий плеер с личным устройством как источником, без комнаты. Пользователь может разрешить этому тайтлу раздачу конкретной комнате. Серверная очередь администратора сохранена в раскрываемом разделе той же страницы; серверные источники плеера не заменены.

## Надёжность и границы

- Команды хранятся в SQL, переживают отключение устройства и сервера. Индексаторный handle разрешается в torrent/magnet до постановки в очередь, поэтому его 30-минутный срок не теряет отложенное задание.
- Устройство получает только свои команды. Веб-операции проверяют владельца, отзыв устройства и Origin; разрешение раздачи дополнительно проверяет права комнаты.
- Повтор доставки использует сохранённую квитанцию; metadata-job сохраняет ID команды вместе с локальной записью. Повтор старта не создаёт вторую загрузку.
- После подтверждения сервер очищает исходный payload команды; завершённые записи старше семи дней удаляются при подтверждении следующих команд.
- Файлы остаются локально. Сервер получает состояния и номера серий, но не локальные пути или файловый IPC.
- Личное воспроизведение использует существующие WebRTC/relay leases с проверкой владельца и идентичности готового файла. Разрешение комнаты не требуется для собственного просмотра, но требуется для других участников.
- Закрытие приложения прекращает хостинг. Компьютер нельзя включить из этой очереди. Для просмотра и управления всё ещё нужен центральный сервер.
- Это интеграция общего текущего интерфейса, а не перенос всей демонстрационной главной страницы из макета. Свободное место и отдельное удаление серий в новой веб-панели пока не добавлены. Расширенные операции остаются в локальных инструментах.
