# Глубокий разбор сюжета: «ИИ смотрит серию» (проект, 2026-10-26)

Задача (IDEAS #79): для выбранного тайтла собрать полный структурированный сценарий серий (реплики, действия, места, кто что знал) и поверх него — граф персонажей, событий и фактов с фильтрами спойлеров и навигацией «как вики». Это единый по глубине слой данных, которого не дают ни теги, ни описания серий, ни вики. Предыдущее исследование источников — `docs/research-plot-sources.md`.

## Вывод
Реалистично при узком скоупе. Главный рычаг — японские субтитры для слабослышащих (SDH, 字幕放送): в них уже есть имена говорящих, звуки и интонации, то есть самая трудная часть (атрибуция реплик) наполовину решена. Видео нужно для действий, мест и того, что не проговаривается. Полный прогон видео дорогой (~10–15 мин GPU на серию), поэтому только для выбранных тайтлов.

Самое ценное и самое сложное — не извлечение, а:
- **модель знания** — наблюдение / вывод, статусы, контексты, время раскрытия, источник;
- **порядок обработки** — слепой прямой проход, потом ретроспективный;
- **поиск под сценарий.**

Схема строится из небольшого набора общих примитивов. Частные случаи (регрессии, воспоминания, маски, филлеры, ненадёжный рассказчик) — это их конфигурации, а не отдельные механизмы. Сложность включается паспортом тайтла только там, где она есть.

## Скоуп первого этапа
- Только тайтлы, у которых есть японские SDH. Без них — не берём (распознавание речи — позже, запасным путём).
- Только выбранные вручную тайтлы:
  - пилот — «О моём перерождении в слизь» (политика, фракции, параллельные линии, рост силы, строительство Темпеста, перерождение);
  - проверка гибкости — «Игра друзей» (каждая игра — событие, ресурсы, доверие, майндгейм);
  - проверка мировых линий — Re:Zero (если найдутся SDH).
- Рекомендации не трогаем. Ранобэ и мангу не подключаем, но схема их сразу учитывает.
- **Перед пилотом** — бумажное упражнение по матрице тайтлов (раздел «Проверка схемы»).
- Перед стартом проверить, есть ли SDH на выбранные тайтлы (jimaku, ТВ-рипы, Netflix).

## Принципы (не нарушать)
1. **Смотрим один раз, думаем много.** Всё, что требует прохода по видео/звуку на GPU (планы, **кадры**, лица, эмбеддинги голоса, описания VLM, текст в кадре), сохраняется сразу и полностью. Текстовые проходы LLM дешёвые и переделываются сколько угодно.
2. **Наблюдение ≠ вывод.** «Прохожих в кадре нет» и «город опустел» — разные записи. Отсутствие на кадре не доказывает отсутствия в мире.
3. **Первый проход — слепой и по порядку.** При разборе серии k модель видит только серии 1…k. Версию «до поворота» нельзя получить вырезанием спойлеров из всеведущей: утечка идёт через формулировки и отбор.
4. **Правильной итоговой схемы не бывает — бывает схема на момент.** Храним все версии, запрос всегда «по состоянию на курсор».
5. **У каждой записи — происхождение:** id реплик/планов-источников, модель, версия промпта, уверенность, статус знания, контекст, момент раскрытия.
6. **Фильтр спойлеров — по моменту раскрытия, а не по месту события в сюжете.**
7. **Источник и ветка канона указываются всегда**, даже пока источник один (аниме).
8. **Общие примитивы, а не заплатки под тайтл.** Новая сложность сначала выражается через существующие примитивы. Новый примитив — только если не выражается, и после проверки на матрице.
9. **Сложность — по включению.** По умолчанию один контекст, одна версия, без рамок. Простой тайтл не платит за сложный ни в извлечении, ни в интерфейсе.
10. **Ручная правка — первоклассная операция:** не перетирается при пересчёте, хранится отдельным слоем.
11. **Узкие схемы.** Модель на 9B точна на 5–10 типах; онтология на 40 типов — шум. Расширять по фактам (механизм расширения).
12. **Противоречия не разрешать молча.** Записывать обе стороны.

## Источники данных

### SDH-субтитры — что сохранить при извлечении
Брать в формате с цветом и позицией (ARIB → ASS с тегами, не SRT; для TS-рипов — декодер ARIB-субтитров, напр. libaribcaption в ffmpeg, проверить).

| Что | Пример | Зачем |
|---|---|---|
| Имя говорящего | `（リムル）` | атрибуция |
| Цвет строки | основные персонажи — постоянный цвет, имя часто только в первой реплике | атрибуция без имени |
| Позиция строки | слева/справа/сверху | кто из собеседников говорит |
| Звуки | `［爆発音］`, `［ドアの開く音］`, `［ざわめき］` | действия и обстановка без зрения |
| Метки голоса | за кадром, телефон, мысленно, телепатия | внутренний монолог, Великий мудрец, «Мысленная связь» |
| Музыка `♪` | опенинг, эндинг, вставная песня, `［不穏な音楽］` | служебные отрезки, атмосфера |
| Фуригана | чтения имён | глоссарий, правильные имена |

### Справочные данные (до прогона)
- AniList: персонажи, роли, картинки, сэйю, **теги с флагами спойлера** (`isMediaSpoiler`, `isGeneralSpoiler`); Shikimori — русские имена.
- Сопоставление серий AniList ↔ TVDB/TMDB — уже есть (`idmap.ts`).
- Видео с японской дорожкой — из библиотеки Jellyfin или через TorrServer.

## Конвейер
Этапы по очереди, через очередь `tasks`, с выгрузкой моделей: всё сразу в 16 ГБ не помещается, видеокарта общая с Jellyfin, Ollama и апскейлером.

**Обработка в два прохода:**
- **Прямой** — этапы 10–11 и 13 по сериям строго по порядку, контекст — только прошлые серии. Результаты неизменны, помечены «на момент серии k». У онгоингов идёт естественно, по мере выхода серий.
- **Ретроспективный** (этап 12) — после арки, сезона, всего тайтла и после каждого крупного раскрытия. Добавляет переосмысления, правки статусов, причинные связи, иерархию событий.

| # | Этап | Инструменты (кандидаты, проверить на пилоте) | Выход |
|---|---|---|---|
| 0 | Справочник и паспорт тайтла | AniList, Shikimori, вики; LLM предлагает паспорт и пакеты, админ утверждает | персонажи, имена ja/ru/en, картинки, паспорт |
| 1 | Субтитры → реплики | парсер ASS/ARIB | `cues`: время, текст, имя, цвет, позиция, тип |
| 2 | Планы и кадры | PySceneDetect, ffmpeg | `shots`: границы, 1–3 кадра (JPG), длина |
| 3 | Служебные отрезки | `♪` в SDH + повтор звука между сериями | опенинг, эндинг, **рекап**, превью следующей |
| 4 | Голос | эмбеддинги WeSpeaker/ECAPA на реплику; отделение голоса (BS-RoFormer/Demucs) — только если мешает музыка | вектор голоса на реплику |
| 5 | Лица | детектор аниме-лиц (YOLO) + эмбеддинги (SigLIP/CLIP) | вырезки, банк персонажей (картинки AniList → дополняется подтверждёнными вырезками) |
| 6 | Описание планов | VLM ~8B (Qwen3-VL или мультимодальная Qwen3.5) по нескольким кадрам плана, ответ строго по схеме | кто в кадре, действие, тип плана, фон, число людей, текст в кадре |
| 7 | Измеримое | ffmpeg/numpy | яркость, насыщенность, палитра, темп монтажа |
| 8 | Места | эмбеддинги фонов (SigLIP/DINOv2) → кластеры, имена из реплик и надписей | места, профиль, таймлайн состояний |
| 9 | Сцены | границы по месту, паузам, составу | `scenes` |
| 10 | Разметка сцен (прямой проход) | LLM `qwen3.5:9b`, structured outputs | говорящий, адресат, манера, присутствие, действия, **рамка** (воспоминание, сон, пересказ…) |
| 11 | Факты серии (прямой проход) | LLM 9B по схеме ядра + включённых пакетов | события, утверждения, знание, изменения трекеров, свободные предикаты |
| 12 | Ретроспективный проход | модель крупнее (MoE ~30B с выгрузкой в ОЗУ) по спискам событий арки/сезона | иерархия событий, причины/следствия, переосмысления, слияние дублей, **«намёки, которые были»** |
| 13 | Сводки | LLM на контрольных точках, для каждой точки зрения | серия, арка, взгляд фракции, страницы сущностей, проза «как ранобэ» |
| 14 | Прицельный переспрос кадров | VLM по сохранённым кадрам с новым вопросом | детали, ставшие важными после раскрытия («есть ли кровь на руках в сериях 2–5») |

Порядок атрибуции говорящего (по убыванию надёжности): имя из скобок → цвет строки (выучен по строкам с именем) → голос по банку → позиция → кто в кадре → контекст (обращения по имени) → LLM сводит. Источник атрибуции хранится в записи (`speaker_src`).

Описание плана VLM — по фиксированной схеме, без свободной прозы. Для изменений места модели передаётся прошлое состояние места и вопрос «что изменилось».

**Монтажные нарезки** (много коротких планов под музыку без реплик) — отдельный тип: «прошло время, произошло X». Строительство Темпеста показывается так.

**Время.** С SDH распознавание речи не нужно: ~10–15 мин GPU на серию (основное — VLM). «Слизь» со всеми сезонами (~70+ серий) — 12–18 ч, то есть несколько ночей. Ретроспективный проход — текстовый, дешёвый.

## Модель данных

### Слои
На диске JSONL по сериям — источник правды: `data/plot/<anilist_id>/<medium>/<unit>/{cues,shots,scenes,annotations,facts}.jsonl` + кадры и вырезки. SQLite — пересобираемый индекс.

1. Исходники (с хэшами) — не меняются.
2. `cues` — реплики.
3. `shots` — планы.
4. `scenes` — сцены.
5. Разметка сцен (прямой проход).
6. Сущности и факты (прямой проход, неизменны).
7. Ревизии ретроспективного прохода (переосмысления, правки статусов, связи).
8. Сводки и страницы (на контрольных точках, по точкам зрения).
9. Ручные правки — поверх всего.

### Семь примитивов
| Примитив | Что это | Примеры конфигураций |
|---|---|---|
| **Сущность** | персонаж, фракция, место, предмет, навык, титул, термин; с личностью и гранями | версии в других контекстах, маски и двойная жизнь (Лойд = Сумрак), перерождение (Сатору Миками → Римуру), обмен телами, клоны, тот же человек дважды в одном времени, алиасы со сроком действия (гоблин → Ригурд) |
| **Контекст** | «мир», в котором верны утверждения | реальность, мировая линия, регрессия, петля, воспоминание, сон, книга в книге, игра в игре, ложь, слух, восприятие персонажа |
| **Событие** | с иерархией (арка → событие → фаза → момент) и разделением шаблон/экземпляр | сценарий и его прохождения по регрессиям, дело в «Конане», матч турнира, игра в «Игре друзей», повторяющийся ритуал |
| **Утверждение** | «субъект — предикат — объект/значение» в контексте, со сроком, областью (глобально / в рамках события) и доказательствами | отношения, состояния, цели, заявления персонажей, передача информации |
| **Знание / убеждение** | утверждение внутри контекста-убеждения держателя | память, ложное воспоминание, знание о чужой маске, «прочитал в романе», подозрение, план |
| **Связь событий** | с типом, при необходимости между контекстами | причина, повод, условие, мотив, последствие, долгосрочное последствие, предотвращение |
| **Подача** | как источник показывает историю | источник (аниме/манга/ранобэ/веб-новелла), порядок подачи ≠ хронология, ветка канона, статус канона (филлер, фильм сомнительной каноничности, альтернативная экранизация — FMA 2003 / Brotherhood) |

### Контексты
Каждое утверждение верно не «вообще», а **в контексте**. Корень — реальность (в ветке канона). Связи контекстов:

| Связь | Примеры |
|---|---|
| ответвление от точки (с причиной) | регрессии, петли Re:Zero, мировые линии Steins;Gate, альтернативные исходы |
| вложенный вымысел | книга в книге, игра в игре, спектакль, симуляция |
| убеждение / память держателя | воспоминание, ложное воспоминание, заблуждение, план, подозрение детектива, искажённое восприятие |
| сообщённое кем-то | рассказ, слух, ложь, пропаганда |
| сон / видение / предположение | сны, пророчества, «что если» |

**Стек рамок у сцены/фрагмента:** «реальность линии X → воспоминание Y о линии Z → пересказ». Правило: **факт из рамки — не факт мира, а утверждение её владельца.**

Географически разные миры (исекай: Земля и другой мир) — это **места**, а не контексты.

### Сущности: личность, версии, грани
- **Личность** («Ю Джунхёк») и **версии в контекстах** («Ю Джунхёк 3-й регрессии»). Отношения, знания, титулы и навыки привязаны к версии; карта по личности сводит их с переключателем контекста.
- **Грани:** маска, псевдоним, тело, форма (Римуру-слизь / Римуру-человек). Кто знает, что за маской, — это знание (утверждение в контексте-убеждении).
- **Разрешение упоминаний:** по умолчанию версия текущего контекста сцены, внутри рамки — версия контекста рамки.
- **Титулы** — отдельные сущности (по ним можно ходить), их получение и потеря — в трекере.

### Утверждения и статус знания — три оси
| Ось | Значения |
|---|---|
| А. Основание (как известно зрителю) | `показано` · `сказано (кем)` · `подразумевается` · `вывод модели` · `не показано` |
| Б. Истинность в контексте | `истина` · `ложь` · `неизвестно` · `спорно` |
| В. Умолчание | `намеренная тайна` · `опущено как очевидное` · `пробел/небрежность` · `неясно` |

| Случай | А | Б | В |
|---|---|---|---|
| Факт | показано | истина | — |
| Сказали, правда ли — неизвестно | сказано (кем) | неизвестно | — |
| Умолчали, но очевидно, что сказали | подразумевается | истина | опущено как очевидное |
| Умолчали, но очевидно, что не говорили | подразумевается | ложь | опущено как очевидное |
| Намеренное скрытие | не показано | неизвестно | намеренная тайна |

**Статус — цепочка свидетельств**, у каждого свой `revealed_at`: в 1 сезоне «сказано/неизвестно», во 2 — «ложь». Ось В без явных сигналов (позже раскрывается, герои уходят от ответа, ракурс прячет лицо) — `неясно`, а не гадать.

### Знание и память
- **Знание:** держатель (версия), что знает, с какого момента, **откуда** — пережил сам / помнит из другой линии / рассказали / прочитал / догадался.
- **Передача информации** («A сообщил B о X») — утверждение со статусами; на нём строится «кто что знал».
- **Воспоминание:** держатель, о каком событии и какого контекста, содержание. **Сверка** с событием, как его показал автор: `совпадает` · `искажено` · `ложное` · `стёрто`.

### Трекеры
Хранятся изменения, а не состояние: «карта X от A к B, ход 5», «Темпест: каменные улицы», «новый навык», «получен титул». Состояние на момент = свёртка изменений до курсора, в нужном контексте. Один механизм для ресурсов, силы, застройки, доверия, знания.

### Наблюдения, интерпретации, противоречия
- Наблюдения и интерпретации — разные типы записей; интерпретация обязана ссылаться на наблюдения.
- **Противоречие** — запись с обеими сторонами.
- **Производственный недочёт** (повтор кадров, нет прохожих, пропал предмет) — отдельная пометка: показывать можно, рассуждать на нём нельзя.
- **Толкование** (символизм, открытый финал) — отдельный вид: несколько версий с источником (автор, фанатская теория), фактом не становится.

## Паспорт тайтла
Определяет, какие примитивы и виды включены. Предлагает LLM по синопсису, тегам и вики, утверждает админ. Правится, когда сложность обнаружилась позже: перегоняются только текстовые проходы.

- **Структура:** сериал / эпизодическая / антология / повседневность без сквозного конфликта.
- **Контексты:** только реальность / петли и мировые линии / вложенный вымысел / ненадёжный рассказчик / сны и видения.
- **Сложности с личностями:** маски, перерождение, двойники, обмен телами, версии.
- **Строгость континуальности:** у гэг-комедий («Гинтама», «Госпожа Кагуя») противоречия — норма, проверка ослаблена.
- **Порядок подачи:** совпадает с хронологией или нет («Монагатари»).
- **Жанровые пакеты.**

По умолчанию всё вырождено. В промпты извлечения попадают только включённые примитивы. Интерфейс скрывает переключатели, если выбирать не из чего: у «Лагеря на свежем воздухе» нет фракций и «почему?», зато есть места, поездки, еда, участники.

## Пакеты жанра
Ядро общее, жанровая специфика — **пакеты** (JSON, версионируются, без кода). Пакет задаёт:
- типы событий и их атрибуты (у «игры» — правила, ставка, ходы, победитель, был ли обман);
- типы отношений и трекеры («контрит», «владеет картой», «уровень силы», «доверие»);
- **что считать событием верхнего уровня** (в «Слизи» — конфликт, в «Игре друзей» — каждая игра);
- подсказки для извлечения;
- виды для интерфейса и шаблоны запросов.

Из схемы пакета генерируется схема structured outputs для Ollama (как уже делает `llm.ts`).

Примеры пакетов: политика (фракции, договоры, территории, асимметрия знаний), рост силы (уровни, навыки, эволюции, ранги, титулы), «кто кого контрит», строительство/развитие (объекты, этапы), игры (партия, правила, ходы, ресурсы, стратегия, обман), майндгейм (планы, уровни предвидения, кто кого раскусил), детектив (дела, улики, подозреваемые, выводы, раскрытие), спорт (матчи, счёт, приёмы), романтика (стадии отношений), повседневность (занятия, места, еда, поездки).

- «Слизь» = политика + рост силы + строительство.
- «Игра друзей» = игры + майндгейм + доверие.

### Механизм расширения
Если факт не ложится в типы пакетов, он сохраняется как утверждение со **свободным предикатом** («X задолжал Y услугу», «X носит маску при Y») и не теряется. Периодически частые свободные предикаты собираются в список кандидатов в новые типы. Админ утверждает — тип добавляется в пакет, перегоняется только текстовый проход. Это важнее, чем попытка всё предусмотреть заранее.

## Повороты и раскрытия
Класс, а не частный случай: кто такой Кира, что такое титаны и стены в «Атаке титанов», кто рассказчик, что было на самом деле в Steins;Gate, китайское аниме про квест-румы, где ГГ, как выясняется в финале, кого-то убил, получил травму и потерял память (ненадёжный рассказчик).

- **Битемпоральность.** У каждой записи два времени: в сюжете (когда это «было») и раскрытия (когда зритель узнал). Запрос всегда «по состоянию на курсор». «Либо некорректно, либо со спойлерами» — ложный выбор: обе версии корректны, каждая на свой момент.
- **Переменная — курсор пользователя, а не «знает ли модель».** Данные в итоге всеведущие. Честность версии «до» обеспечивается слепым прямым проходом.
- **Переосмысление на уровне контекста.** При раскрытии добавляется одна запись: «контекст „реальность как подано“ с серии 1 по N — это восприятие ГГ; раскрыто в серии N» + новые факты настоящей реальности. Тысячи фактов первых серий не переписываются, статус вычисляется при запросе.
- **Основная масса данных при повороте не меняется.** Что показано и кто что сказал — стабильно. Меняется тонкий слой: контекст и истинность. Поэтому наблюдения и толкования разделены.
- **Двойной поворот** (раскрытие потом опровергается) — та же цепочка ревизий.
- **Версия «до» — ценность:** вид «что выглядело так, а оказалось этак» и **«намёки, которые были»** — сцены, чей смысл сменился при раскрытии, со ссылками на серию и время. Это автоматический пересмотр.
- **Прицельный переспрос кадров** (этап 14): детали, ставшие важными после раскрытия, VLM при первом проходе могла не записать. Поэтому кадры хранятся, а не только описания.

## Визуальный слой: как не уйти в неверные выводы
**Лестница доказательств** (сверху сильнее):
1. сказано в реплике или закадром;
2. звук в SDH (`［ざわめき］` опровергает «улицы пусты»);
3. повторяется в нескольких планах/сериях;
4. реакция персонажей;
5. один кадр.

Вывод по одному кадру — «слабый», в причинные связи сам по себе не попадает.

**Базовая линия тайтла:** как часто в нём рисуют толпу там, где она точно есть (рынок, столица со слов героев). Если почти никогда — пустая улица не сигнал. Считать по тайтлу и по сериям: аутсорс-серии хуже.

**Атмосфера** («все в напряге», «экономно, но со вкусом») — всегда интерпретация из сочетания: реплики + звук и музыка в SDH + реакции + измеримая палитра. По одной картинке модель фантазирует.

**Места:** профиль (облик, материалы, масштаб, атмосфера) + таймлайн состояний по появлениям. Описания из ранобэ позже добавляются отдельными свидетельствами с источником `LN`, не переписывая увиденное в аниме.

## Аниме, манга, ранобэ, веб-новелла
- **Подача по источникам:** аниме — серия/сцена, ранобэ — том/глава/абзац, манга — глава/страница/панель. Извлечение отдельно по каждому, одной схемой.
- **Ветки канона:** у «Слизи» веб-новелла заметно расходится с ранобэ; аниме и манга — в основном по ранобэ. Между ветками факты не сливаются автоматически. Филлеры — статус канона в подаче аниме.
- **Сопоставление** сцен ↔ фрагментов (многие ко многим), типы: `адаптировано` · `сокращено` · `изменено` · `добавлено только в аниме` · `вырезано` · `переставлено`.
- **Для зрителя важна неочевидность в аниме:** если в аниме не ясно, а в ранобэ ясно, — это один факт с разными свидетельствами по источникам, а не «истина из ранобэ».

## Точки зрения и фильтры спойлеров

### Три точки зрения — один граф, разные фильтры
| Точка зрения | Что видно |
|---|---|
| **Всеведущий** | все контексты, все факты, курсор выключен |
| **Персонаж (версия) на момент** | только его знание с источниками: «что знал X, когда…» |
| **Я как зритель/читатель** | всё, что раскрыто до моих курсоров |

### Курсоры и режимы
- Положение пользователя — **курсоры по источникам**: `anime: s1e24`, `LN: —`, `WN: —`.
- Фильтр по `revealed_at`. Факт о событии 1 сезона, раскрытый во 2-м, при курсоре `s1e24` не виден.
- Режимы:
  - «как зритель аниме»;
  - «аниме + первоисточник до того же места» (по сопоставлению);
  - «до конца сезона»;
  - «всё»;
  - ручные курсоры.
- Производные тексты готовятся на контрольных точках (конец каждой серии для «только аниме», конец сезона) **для каждой точки зрения**. Остальное — на лету из отфильтрованных фактов.

### Гигиена спойлеров (шире, чем фильтр фактов)
- **Теги:** сам тег «ненадёжный рассказчик» — спойлер. Учитывать флаги спойлера AniList; свои теги из сюжета — с `revealed_at`.
- **Производные тексты:** сводки, карточки, названия достижений, «похоже на…».
- **Структура:** ребро «убийца — жертва» на карте, счётчик «??? скрытых узлов: 3» — уже намёк.
- **Выводы модели:** если модель по намёкам догадалась раньше раскрытия, в режиме «я» это не показывать. Выводы за пределами показанного по умолчанию скрыты.
- **Собственные знания LLM:** про популярные тайтлы модель знает финал из обучения. Инструкция «только из переданного» + проверка, что каждое утверждение ответа ссылается на разрешённый узел. Для популярных тайтлов риск полностью не убрать.

## Хранение и поиск
**SQLite:**
- `contexts` (тип, родитель/связь, точка ответвления);
- `entities`, `versions`, `aliases` (со сроком);
- `events` (`parent_id`, шаблон/экземпляр, контекст, порядок в мире);
- `roles`;
- `assertions` (субъект, предикат, объект/значение, контекст, область-событие, срок);
- `evidence` (три оси, `revealed_at`, проход, источник, ветка, реплики/планы, модель, версия промпта, уверенность);
- `revisions` (переосмысления контекстов и правки статусов);
- `event_links` (тип связи);
- `deltas` трекеров;
- `chunks` + FTS5 + векторы;
- `passports`, `packs`;
- `overrides` (ручные правки).

Общие поля — колонками, поля пакета — JSON с проверкой по схеме пакета. Отдельная графовая БД не нужна: на тайтл десятки тысяч узлов, хватит рекурсивных запросов SQLite.

**Чанки по смыслу, не по токенам:** сцена (текст сценария), фаза/событие/серия/арка (сводки), страницы сущностей на курсор. Метки: источник, единица, контекст, `revealed_at`, точка зрения, id сущностей и событий. Фильтр по курсору — **до** поиска. Поиск гибридный: FTS5 (BM25) + `bge-m3`; на один тайтл достаточно перебора.

**Виды под сценарии** (шаблон запроса к графу + подбор доказательств; LLM — только где нужен текст):
- **Карта персонажей.** Персонажи (по личности, с переключателем контекста) + отношения на курсор + вес по совместным сценам. Без LLM.
- **Карточка события.** Фазы → участники с ролями → утверждения в рамках события + отношения между участниками на тот момент → причины и следствия (1 шаг) → 3–5 сцен-доказательств.
- **«Почему / зачем» (мотив).** Действие → цели версии персонажа на тот момент → его знание на тот момент с источником → предшествующие события по связям → его слова и монолог в сцене → последствия. Ответ кэшируется по ключу «узел + точка зрения + курсор».
- **Сценарий по контекстам.** Шаблон + таблица прохождений по линиям/регрессиям: что изменилось и почему.
- **Игра/партия.** Ходы по порядку → трекер ресурсов после каждого хода → заявленные и раскрытые стратегии.
- **Место.** Профиль + таймлайн состояний + ключевые кадры.
- **Намёки и переосмысления.** Что выглядело так, а оказалось этак (после раскрытия).
- **Чат по тайтлу.** Агент с инструментами: найти сущность по алиасу → раскрыть подграф → гибридный поиск по чанкам → состояние трекера на момент. Ответ — со ссылками на серию и время, с учётом курсоров и точки зрения. Обзорные вопросы — через сводки арок.

## Навигация — сгенерированная вики поверх графа
Пример пути: персонаж → вкладка «Титулы» → титул (когда получен, в каком прохождении) → сценарий (краткое/полное описание, прохождения по линиям) → «Почему?» на действии → вид «мотив» → связанные события → их последствия → …

- **Типы страниц:** персонаж (личность и версии), титул, сценарий/шаблон, прохождение/экземпляр, событие, место, фракция, предмет/навык, контекст (мировая линия).
- **Краткое и полное описание** на каждой странице — заранее на контрольных точках и для каждой точки зрения.
- **На каждой странице:**
  - переключатели контекста и точки зрения + курсор (показываются, только если паспорт их включает);
  - «хлебные крошки» пройденного пути;
  - мини-граф окрестности узла.

## Что это даёт (потребители)
- Подробные сводки серий и улучшенный «Что было раньше» (`plot.ts`), «напомни перед серией» без спойлеров.
- Чат по тайтлу с границей спойлеров (закрывает IDEAS #5 на глубоком уровне).
- Вики тайтла: персонажи, титулы, сценарии, события, места, фракции — с переходами и «почему».
- Карта персонажей с картинками, отношениями во времени, именами и версиями.
- Карта событий с причинами, следствиями и доказательствами.
- Взгляд фракций: цели, знание, действия.
- Достижения тайтла: сюжетные и мемные кандидаты, срабатывание по серии, модерация админом.
- Глоссарий (имена, навыки, места, термины с русскими названиями) — потом для перевода манги и субтитров надписей.
- Позже: сопоставление с ранобэ, признаки для рекомендаций (с уверенностью и источником, чтобы глубокие и поверхностные тайтлы оставались сравнимыми).

## Проверка схемы (до кода)
Гарантировать полноту заранее нельзя, поэтому — проверка на разнообразных тайтлах.

**Бумажное упражнение:** вручную смоделировать 1–2 серии/главы каждого тайтла матрицы в этой схеме (JSON руками). Плюс **банк вопросов** к каждому — 5–10 типичных вопросов зрителя («что Лойд знает о способностях Ани», «чем отличается 2-я петля от 3-й», «где они ели в 4-й серии», «зачем он сломал трон»). Схема достаточна, когда на вопросы отвечают виды без новых примитивов. Каждая дыра на бумаге — дешёвая.

| Тайтл | Что проверяет |
|---|---|
| «Слизь» | фракции, параллельные линии, рост силы, строительство, перерождение |
| «Игра друзей» | игры как события, ресурсы, доверие |
| Re:Zero | петли, помнит один |
| Steins;Gate | мировые линии, один человек дважды, изменение прошлого |
| «Всеведущий читатель» | регрессии, версии персонажей, книга в книге, титулы, ненадёжный рассказчик (текст) |
| Китайское аниме про квест-румы (название уточнить) | ненадёжный рассказчик, переосмысление всего в финале |
| «Семья шпиона» | маски, кто о ком что знает, полуэпизодичность |
| «Мусиси» / «Детектив Конан» | антология / дела как шаблон |
| «Лагерь на свежем воздухе» | повседневность без конфликта |
| One Piece | масштаб, филлеры, огромный состав |
| FMA 2003 / Brotherhood | альтернативная экранизация одного источника |
| «Монагатари» | порядок показа ≠ хронология |
| «Волейбол!!» | матчи, счёт, трекеры |
| «Госпожа Кагуя» | майндгейм в ромкоме, гэговая континуальность |
| «Евангелион» | толкования вместо фактов |

## Оценка качества
До масштабирования — вручную размеченный эталон одной серии: сцены, говорящие, ключевые события, места, рамки.

Метрики:
- доля верно атрибутированных реплик — отдельно по имени, по цвету, по голосу, по выводу;
- полнота ключевых событий против эталона и вики;
- доля ложных интерпретаций визуального;
- **утечки спойлеров:** версия «на момент серии k» не содержит сведений из серий > k (проверка вопросами из банка);
- время на серию по этапам.

Ориентир: атрибуция реплик основного состава с SDH — 90%+ (уточнить на пилоте). Каждое изменение промпта или модели прогонять на эталоне.

## Риски
| Риск | Что делать |
|---|---|
| Схема подгоняется под один тайтл | семь примитивов, матрица, бумажное упражнение, механизм расширения |
| Дубли сущностей и событий («Барусу» = Субару) | справочник алиасов с AniList/Shikimori заранее; экран «возможные дубликаты» |
| Неверная версия персонажа или рамка (воспоминание принято за реальность) | паспорт тайтла, метки рамок в разметке сцен, ручная правка; модель не определит сложную структуру контекстов сама |
| Утечка спойлеров через формулировки, теги, структуру, знания LLM | слепой прямой проход, гигиена спойлеров, проверка на банке вопросов |
| Границы событий спорны | разбиение — в ретроспективном проходе; правка админом, не перетирается |
| VLM плохо видит динамику (кто ударил первым) | экшен описывать крупно; опираться на звуки SDH и реплики |
| Детали, важные после раскрытия, не записаны | хранить кадры, прицельный переспрос (этап 14) |
| Выдуманные причинные связи | у связи обязательна цитата/сцена; «сказано» отдельно от «выведено» |
| Большой состав, похожие монстры | узнавание по лицу — для основного состава; остальные по именам в репликах или «неизвестный» |
| Толкования и символизм («Евангелион», «Утэна») | отдельный вид «толкование» с версиями и источником, без превращения в факты |
| Тонкая режиссура (взгляд, намёк) | признать пределом; не выдавать отсутствие за факт |
| Метасюжеты (регрессии, сверка памяти) на 9B | ретроспективный проход и «мотив» — на модели крупнее; больше ручной правки |
| Одна видеокарта | этапы по очереди, ночью; не мешать просмотру в Jellyfin |
| Переусложнение | ядро + 1–2 пакета на пилот, паспорт выключает лишнее, расширять по фактам |

## Порядок работ (максимум пользы на каждом шаге)
0. **Разведка и бумага.**
   - Есть ли SDH на тайтлы пилота; формат (ASS/ARIB/SRT), сохраняются ли цвет и позиция.
   - Бумажное упражнение по матрице + банки вопросов; правка схемы по найденным дырам.
   - Разметить эталонную серию.
1. **Только текст из SDH, без видео, прямым проходом.** Реплики → сцены (по паузам и смене состава) → говорящие → факты и события ядра. Уже даёт чат, сводки, карту персонажей. Дёшево, проверяет схему и отсутствие утечек.
2. **Видео.** Планы, кадры, служебные отрезки, лица, описания VLM, места и их таймлайн, монтажи. Сравнить с этапом 1 на эталоне: что добавило зрение.
3. **Паспорт, пакеты и ретроспективный проход.** Политика + рост силы + строительство для «Слизи»; иерархия событий, причины, трекеры, цели и знание фракций, переосмысления.
4. **Вики и виды в интерфейсе.** Страницы сущностей, карта персонажей, карточка события, «почему», место, чат с курсорами и точками зрения.
5. **Проверка гибкости:** «Игра друзей» (игры, ресурсы), Re:Zero (контексты-петли).
6. **Дальше по решению:**
   - ранобэ/веб-новелла и сопоставление; «Всеведущий читатель» как стресс-тест;
   - достижения тайтла;
   - распознавание речи для тайтлов без SDH (faster-whisper/WhisperX, anime-whisper, kotoba-whisper + pyannote `community-1`);
   - признаки для рекомендаций.

## Вне скоупа первого этапа
