# R4 — управление разрешением ИИ

Первый сценарий согласован владельцем 20.11.2026. Сохранение остатка перерыва
не входит в реализацию. Постоянные эксплуатационные выключатели отличаются
от временных экспериментов с двумя реализациями.

## Установка

В установщике: `--modules flags` (можно сочетать с `search,llm`). Для уже
установленного сервера после обновления служебных файлов:

```sh
sudo /opt/home_theater/home-theater module flags on
```

Unleash OSS 8.3.1 использует отдельную БД и роль `unleash` в существующем
PostgreSQL. Образ закрепляется digest после первого скачивания. Порт 4242
доступен только на loopback. При публичном HTTPS панель открывается по
`https://<сервер>/unleash`. При локальной проверке нужен SSH-туннель к 4242.
Доступ к панели — отдельный администратор Unleash; обязательного SSO нет.
Сгенерированные имя и пароль находятся в закрытом `server.env` в полях
`UNLEASH_DEFAULT_ADMIN_USERNAME/PASSWORD`. После смены пароля в панели эти
поля остаются первоначальными, а не способом сброса текущего пароля.

Приложение получает отдельный backend-токен проекта `default`, окружения
`production`, без административных прав. Токен хранится только в закрытом
`application.env`; браузер/desktop не получают его, стратегии или секреты.
Готовая панель Unleash ведёт историю изменений. При первом подключении все
четыре выключателя выключены: владелец включает нужные явно.

## Семантика

| Флаг | Разрешает новые операции |
|---|---|
| `ai-enabled` | Общий допуск ко всем нижеперечисленным операциям |
| `ai-shared` | Общие анализы, переводы текста, эмбеддинги, диагностический LLM-запрос |
| `ai-personal` | Портрет вкуса и персональное переранжирование рекомендаций |
| `ai-media` | Зрение LLM, OCR, перевод страниц манги, апскейл изображений |

Для выполнения нужны общий флаг **и** флаг категории, доступный провайдер,
существующие права и ограничения приложения. Флаги не запускают контейнеры
и не заменяют разрешения пользователей. Сохранённые данные остаются в БД;
провайдерные проверки не закрывают чтение готовых результатов.
В этом инкременте решения общие для сервера. «Персональные» обозначает тип
ИИ-задач, а не отдельный пользовательский бюджет или адресное включение
для аккаунта. Пользовательский rollout требует отдельной передачи контекста
в запросы и фоновые задания; он здесь не реализован.

SDK опрашивает Unleash раз в 5 секунд и вычисляет стратегии на сервере.
Выключение действует после получения обновления, перед очередным сетевым
запросом к провайдеру, в том числе после ожидания и перед повторной попыткой.
Фоновая задача, получившая запрет, остаётся в очереди без повторных попыток
до включения категории; затем запускается повторно с имеющимися результатами.
Текущая общая очередь при рестарте процесса по-прежнему помечает незавершённые
задания прерванными; непрерывное восстановление всех задач этой вехой не обещается.
Уже отправленные запросы не отменяются; экономия их стоимости не обещается.
Видео и синхронизация просмотра этими выключателями не управляются.

Без когда-либо настроенного Unleash сохраняется существующее поведение ИИ.
Если адрес или токен заданы, но нет корректного снимка, генерация запрещена
до успешной синхронизации. При сбое используется последний корректный снимок
в `data/feature-flags`, включая пустой список после удаления флагов. Кэш
разделён по адресу, окружению и токену; перезапуск не делает сетевой сервис
обязательным для открытия приложения. Ошибка записи кэша видна в диагностике.
Утраченная связь не гарантирует применения нового отключения из панели.

Независимое локальное отключение без рестарта:

```sh
sudo /opt/home_theater/home-theater flag ai-enabled off
sudo /opt/home_theater/home-theater flag ai-enabled release
```

`release` снимает только локальный запрет, не принуждает включить ИИ.
Изменения записываются в `data/feature-flags/local-events.jsonl`. Повреждённый
файл локальных запретов запрещает ИИ до исправления. Переменная
`FEATURE_FLAGS_FORCE_OFF` позволяет дополнительно запретить имена через
запятую; изменение этой переменной требует пересоздания процесса.

Администратор видит компонент в существующем списке модулей. Состояние
вычисления флагов без секретов: `GET /api/admin/feature-flags` (только admin).
Отключённая генерация возвращает понятную ошибку `feature_disabled`, HTTP 503.

`module flags off` останавливает сервис управления, сохраняет его БД,
конфигурацию приложения и кэш решений. Это **не** выключение ИИ: для него
используется `ai-enabled off`. Повторное подключение сохраняет значения.
Резервная копия включает отдельный дамп Unleash даже при остановленном модуле.
Восстановление создаёт новую БД с прежними значениями и backend-токенами,
сохраняя пароль PostgreSQL целевой установки.

## Жизненный цикл

Реестр — `src/lib/feature-flags.ts`. Четыре текущих флага постоянные, задачи
удаления для них не нужны. Временный эксперимент обязан содержать владельца,
ссылку/номер Issues на удаление, релиз пересмотра и область `session`.
Срок — напоминание, а не автоматическое удаление. Отдельный PR удаления
требует приёмки, проверки реальных сценариев, отсутствия блокирующих ошибок,
окончания миграций и зависимостей от старой обработки. Для такого эксперимента
отдельно реализуются и проверяются фиксация решения на комнату и аварийный
переход в безопасное состояние; ИИ-выключатели не доказывают этот протокол.

## Ограничения

Существующий месячный предел расходов не резервирует бюджет параллельных
запросов. Пользовательские квоты, резервирование, BYOK и полный пересмотр
ИИ-кэширования остаются отдельной работой. Флаги — управление допуском,
а не гарантия денежного лимита.

Боевой сервер обновляется только в выбранное владельцем окно обслуживания.
Сборка и тестовое развёртывание не означают приёмку или обновление production.
