# М8 — приёмка release candidate

Версия desktop: **0.3.1-rc.1**, протокол 2. Сервер и все хосты обновлять между сеансами. Автообновления и подписи установщика пока нет. Этот документ — воспроизводимый сценарий, а не отметка о прохождении всех пунктов.

## Windows

1. Скачать NSIS `home_theater-0.3.1-rc.1-win-x64.exe` и сверить SHA-256 с `apps/desktop/release/SHA256SUMS-0.3.1-rc.1.txt` командой `Get-FileHash -Algorithm SHA256 <путь>`.
2. Закрыть desktop после окончания подготовки и раздачи. Запустить установщик для текущего пользователя; при обновлении выбрать прежнюю папку. Не удалять пользовательский профиль.
3. Открыть приложение: должны сохраниться адрес сервера, библиотека и подготовленные серии. Привязка должна сохраняться на том же аккаунте ОС с доступным хранилищем ключей. Изолированная локальная проверка М8 проверяет библиотеку и настройки; перенос зашифрованного токена между аккаунтами не обещается.
4. Проверить привязку через браузер, разрешение тайтла комнате и воспроизведение в браузере другого участника. Desktop держать открытым.

## Arch — отложено до появления устройства

Основной пакет — x86_64 AppImage, не AUR/PKGBUILD. Хранить версии отдельно, например в `~/Applications`; обновление — скачать новый файл, проверить хеш, закрыть старый процесс и запустить новый. Профиль `~/.config/home-theater-desktop` не удалять. Дистрибуция пока ручная, публичного updater feed нет.

1. Скопировать AppImage, контрольную сумму и `apps/desktop/test/check-arch-package.sh`. Выдать AppImage право исполнения (`chmod +x <файл>`).
2. Выполнить `bash check-arch-package.sh <AppImage> <SHA256 из файла сумм>`. Скрипт проверяет архитектуру, хеш и runtime, не меняет систему.
3. Запустить AppImage обычным пользователем без `--no-sandbox`. Проверить отдельно доступные Wayland/X11 сеансы. Если отсутствует FUSE либо системная библиотека, записать точную ошибку; не отключать sandbox ради зелёного результата.
4. Проверить браузерную привязку и повторный запуск. При недоступном защищённом хранилище Linux приложение не должно сохранять токен открытым текстом; повторная привязка в таком окружении — известное ограничение.
5. Подключить тестовый файл, подготовить, перезапустить приложение: оригинал, запись библиотеки, подготовленный файл должны сохраниться. Подготовка после принудительного завершения должна быть доступна повторно.
6. Для проверки обновления сначала открыть 0.3.0-alpha.1 с отдельным профилем `--user-data-dir=<абсолютная тестовая папка>`, добавить файл, закрыть. Открыть 0.3.1-rc.1 с тем же аргументом. Сверить библиотеку и подготовленный SHA-256; проверить воспроизведение новым хостом. Старый клиент текущий сервер отклоняет с требованием обновления — это ожидаемо.
7. Проверить отмену раздачи, отзыв устройства и запуск после сна/пробуждения. Удаление AppImage не должно удалять оригинальные медиа.

## Совместный просмотр через интернет

Нужны доступный HTTPS-сервер, два аккаунта — участника комнаты, два независимых подключения. Минимум Windows/Chromium и Arch/Chromium; Firefox, Android Chrome, iOS Safari и ТВ проверять отдельно, не считать совместимыми по результату Chromium на Windows.

| Сценарий | Ожидаемый результат |
|---|---|
| План A→B и B→A, серии 1/3/7 | Точный порядок, пропуски не заполняются |
| Перерывы 0 и 1 минута, отмена у нуля | Общий отсчёт; выключенное автопродолжение ждёт управляющего |
| Полный экран, конец серии | Следующая серия без выхода из fullscreen и повторной готовности |
| Поздний вход / приглашённый не вошёл | Вход на общую позицию; приглашённый не блокирует |
| Потеря хоста при достаточном буфере | Та же подготовленная SHA-256 и размер; автоматическая передача без паузы |
| Буфер закончился у одного | Общая пауза; восстановление всех либо «Продолжить без ожидающих» |
| Возврат исключённого зрителя | Синхронизация на текущую позицию; снова участвует в барьере |
| Другая кодировка / отозванное разрешение | Не используется как автоматическая замена |
| Потеря центрального сервера / перезапуск | Управляемая пауза, восстановление состояния; никакого незаметного пропуска плана |
| Ручная пауза, затем обрыв | Восстановление связи не отменяет ручную паузу |
| Офлайн-встреча, исправление истории | Конкретные серии, выбранные участники, отдельная исправляемая запись |
| Пересмотр, ожидание релиза | Личный цикл независим от истории комнаты; ожидание релиза не считается неактивностью |

Провести несколько реальных вечеров. Для каждого сохранить: версии ОС/браузера/desktop/сервера, direct или relay, число зрителей, выбранные серии, запас буфера перед разрывом, время восстановления, результат и повторяемые шаги ошибки. Не прикладывать токены, cookies и личные пути файлов.

Цели измерений: p95 расхождения ≤500 мс, стабилизация после seek/переключения ≤3 с. Единичный локальный замер не подтверждает p95. Измерять на серии наблюдений двух зрителей с общим временем замера.

## Допуск и откат

До успешных Arch/WAN/реальных вечеров — RC, не stable. Нельзя считать каталог браузеров проверенным по одному локальному сеансу. При проблемах автохостинга администратор может задать `DESKTOP_HANDOVER_ENABLED=0`; HTTP relay управляется отдельно `DESKTOP_RELAY_ENABLED`. Отключение relay при отсутствии прямой связи делает просмотр невозможным.

Для отката сервера М8 использовать сохранённый образ М7; схемы БД М8 не меняет. Остановить текущий просмотр перед обновлением/откатом. Старую серверную версию и desktop проверять вместе; старый desktop не использовать с сервером М8. Профили/оригиналы при откате не удалять.
