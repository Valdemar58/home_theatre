# Страница тайтла · 2026-11-19

Общий компонент AnimeDetailsView для веба и desktop. Непрерывные разделы: описание, мир и персонажи, кадры/видео, франшиза, похожее, обсуждение. «Барабан» слева — якорная навигация, текущий пункт определяется прокруткой; фиолетовая направляющая, масштаб и наклон пунктов, hover и клавиатурный фокус. На узких экранах — горизонтальная навигация. Reduced motion отключает плавные переходы.

Основное действие «Смотреть» ведёт сразу в плеер, даже без подготовленной серверной копии. Вышедшие серии определяются каталогом, а не наличием файла. Когда вышло 5 и просмотрено 5, шестая не предлагается до объявленного времени. Таблица справа сохраняет статус выхода, даты, день/часовой пояс, страну, первоисточник, студию, популярность. Впечатления — ниже таблицы. Подготовка и загрузки доступны через «Ещё»; сериям с описаниями отведён плеер.

Проверки: TypeScript; 21 тест правил выхода серий/цели просмотра/плана. Финальные визуальная проверка и deployment записываются ниже после выполнения.

## Desktop и публичный доступ

При первом запуске: «Адрес сервера» → https://pivocinema.duckdns.org → «Привязать аккаунт». В браузере войти в тот же аккаунт, сверить код, выбрать «Это моё устройство». Вернуться в приложение. Устройство доступно вебу в «Мои устройства» и «Загрузки». Приложение должно работать для загрузки и раздачи; разрешения комнатам выдаются отдельно.

Caddy и ddns найдены остановленными около пяти дней; приложение и база работали. Контейнеры запущены. HTTPS из Linux-контейнера со штатной проверкой TLS: HTTP 200, страница /login. Windows curl отдельно сообщил недоступность проверки отзыва сертификата; проверку сертификатов не отключали. Причина прежней остановки контейнеров не установлена.

Во время сборки диск C заполнился. Удалён неиспользуемый Docker build cache (21.42 GB внутри виртуального диска) и воспроизводимый .next/cache текущего worktree (~500 MB на C). Docker оказался в состоянии stopping; пользователь разрешил его перезапуск с учётом других контейнеров. Первая попытка новой резервной копии завершилась I/O error и не считается пригодной копией.

Восстановление Docker: два каталога runtime-сокетов сохранены под именами `run.stale-20261119` и `docker-secrets-engine.stale-20261119`; исходные сокеты Windows не позволяла открыть/удалить. После запуска Docker пользователем контейнеры приложения, авторизации, базы, Caddy, DDNS и asu_mks восстановлены. Заводской сброс не выполнялся. Проверка публичного HTTPS повторно дала HTTP 200 /login.

Исправная резервная копия перед обновлением: `/data/backups/pre-title-ui-20261119-final.dump`. Полный набор: 559 passed, 1 skipped. Образ собирается поверх предыдущего рабочего runtime (Dockerfile.title-ui), без обновления системных медиазависимостей.
