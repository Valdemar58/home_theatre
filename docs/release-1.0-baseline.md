# Исходное состояние перед 1.0

Проверка начата 19 ноября 2026. Это реестр доказательств и пробелов, а не
подтверждение готовности 1.0. Предыдущие отчёты описывают прошлые сборки;
непроверенные сценарии не считаются автоматически исправными.

## Порядок закрытия исходной проверки R1.4

1. Проверить локальный рабочий сервер read-only, состояние интеграций и доступные
   сценарии; активный просмотр и пользовательские данные не изменять без задачи.
2. В изолированном окружении пройти вход, комнату/редактор, прогресс, подбор
   torrent/magnet, подготовку и playback, ручные/автоматические переходы.
3. На каждую воспроизводимую старую неисправность — Issue со сценарием и влиянием.
4. Владелец отдельно принимает перенос конкретных дополнительных функций.
5. R1.4 не закрывается по зелёному CI или по этому первоначальному списку.

## Обнаруженные риски воспроизводимости

- Корневой системный `npm` в данной Windows-сессии ссылается на отсутствующий
  npm-cli. Для локальной проверки использованы установленные Node/Vitest/tsc
  напрямую; hosted CI устанавливает свой Node/npm.
- Сборка шрифта Inter зависит от доступности Google Fonts при сборке.
- Старый `database/backup-check.mjs` ожидает ровно две миграции, хотя миграций уже
  больше. Перед включением проверки восстановления в release gate нужно сравнивать
  фактическую историю до и после, а не константу; это не проверено исправлением здесь.
- Предыдущие одноразовые Dockerfile опирались на локальные образы. Они не входят
  в публикуемый набор; основная серверная сборка использует основной Dockerfile.
- Первый PostgreSQL CI выявил гонки фикстур: несколько файлов очищали общие
  таблицы одновременно. Для POSTGRES_TEST включён последовательный запуск файлов;
  SQLite с отдельными временными БД продолжает выполняться параллельно.

Скриншоты и локальные доказательства предыдущих проверок остаются локальными,
поэтому исторические ссылки на них в старых отчётах могут не открываться на GitHub.
