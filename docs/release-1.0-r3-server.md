# R3 — серверный кандидат

R3.1–R3.3 приняты владельцем 20 ноября 2026. PostgreSQL остаётся в контейнере
с постоянным томом для 1.0. Нативная установка и готовая система контроля
бэкапов/восстановления отложены за 1.0 ([#70](https://github.com/Valdemar58/home_theatre/issues/70)).
Ниже сохранены исторические проверки инкрементов; актуальный результат R3.4 — в конце.

перезапуска в настоящем Electron подтверждены dev-адрес и прежний личный аккаунт.
БД домашней установки сохранена; в БД VPS личные данные не переносились.

- Диагностика компонентов и независимый от Sonarr поиск реализованы R3.2;
  доказательства приведены ниже. Ollama без скачанной модели требует настройки;

- Установщик на VPS обнаружил готовый Docker. Ветка установки Docker проверена
  дополнительно на чистом Ubuntu 24.04 в отдельном WSL-дистрибутиве.
- Публичный пакет в Releases и стабильный выпуск остаются задачами R7;

## Дополнительная чистая установка

Использован официальный Ubuntu 24.04.5 amd64 WSL-образ; SHA-256 сверён с
опубликованным Ubuntu списком. До запуска отсутствовали Linux Docker, сокет
Docker и Compose; Windows Docker исключён из PATH. Установщик установил Docker
29.10.0 и Compose 5.8 через официальный APT-репозиторий, включил systemd-службу
Docker и поднял приложение с PostgreSQL. Readiness успешен.

Первоначально DNS внутри этого одноразового WSL не разрешал registry; исправлена
только сеть тестового дистрибутива, затем установка завершилась. Это проверка
чистого Ubuntu userspace и установки зависимостей, а не проверка отдельного
VPS-ядра. Реальный VPS, публичный DNS и HTTPS проверены отдельно выше.

## R3.3 — резервное копирование и восстановление

Проверено на отдельной БД и отдельных контейнерах VPS; личная БД не затронута:

- Архив проверяется по manifest/SHA-256, права 0600, медиа не включаются.
- После создания копии добавлена комната; восстановление выбрало новую БД,
  сохранило исходную БД, вернуло исходную комнату без более поздней записи.
- Сохранены ID пользователя, действующая браузерная сессия, SESSION_SECRET и
  desktop-токен; авторизованный запрос устройства после восстановления успешен.
- Ежедневный systemd-таймер создан и остаётся выключенным.
- PostgreSQL backup-check сверяет данные UTF-8 и полную историю миграций;
  повторное восстановление в непустую БД отклоняется (#37).
- 15 Linux contract tests: повреждение архива, выход путей за каталог, ссылки,
  несовместимый образ, исключение медиа и возврат каталога при ошибке переключения.

Ограничения: офлайн-копия кратко останавливает пишущие сервисы и запрещена при
активном просмотре; восстановление требует тот же digest приложения. Локальная
копия не защищает от потери VPS. Старые БД и каталоги намеренно сохраняются;
их очистка выполняется отдельно после приёмки восстановления.

## Дополнение по повторной установке и dev

Во время дополнительной проверки сетевой тайм-аут registry воспроизвёл лишнюю
зависимость повторного запуска от внешней сети. Исправлено: если все нужные
образы закреплены по digest и присутствуют локально, `up` не обращается к
registry. Отсутствующий образ или новый модуль по-прежнему требует загрузки.
Повторная установка также завершает создание выключенного таймера, если первая
попытка оборвалась после записи конфигурации. Добавлена проверка этого контракта;
всего 16 Linux tests.

Домашний dev обновлён проверенным образом R3.2 после резервного копирования БД.
Сохранены пользователь ID 1 и активная привязка desktop; HTTPS readiness успешен.
Новая диагностика доступна администратору в настройках. Основной VPS-кандидат
этим действием не обновлялся; R3.4 ещё предстоит реализовать.

## R3.4 — проверенное окно обслуживания, 20 ноября 2026

Код принят в main через [PR #71](https://github.com/Valdemar58/home_theatre/pull/71),
[PR #72](https://github.com/Valdemar58/home_theatre/pull/72) и

Итоговый кандидат `94aff2a816bf2016b4c81eb8bc1a046286b21630`:
[CI и пакет 44746904619](https://github.com/Valdemar58/home_theatre/actions/runs/44746904619).
Все проверки и публикация успешны; скачанный архив сверён по SHA-256 и source commit.

На отдельной Ubuntu VPS-установке с собственными БД/контейнерами проверены:

- Настоящий переход между образами кандидатов `3d1751f` → `43a1669` → `94aff2a`
  через systemd-таймер, предобновительный архив, запуск и readiness.
- В начале окна новые просмотры получают 503, текущая комната сохраняет позицию
  и остаётся на паузе после перезапуска; личная позиция также сохраняется.
- Cookie-сессия, ID владельца, комната и desktop bearer token работают после
  обновления и после принудительно спровоцированного отказа кандидата.
- Установка старого образа без maintenance API отклонена проверкой готовности;
  возвращены прежний образ и данные через новую БД, исходная БД оставлена.
- Реальный POST desktop с недопереданным телом удержан через начало окна и
  десятисекундный интервал финального прогресса. Подтверждение готовности содержит
  незавершённую запись; обновление начинает бэкап только после окончания POST.
- Последний CI-пакет действительно установлен на стенд. В нём проверено время
  с дробными секундами: план и OnCalendar совпадают до секунды.
- Отмена будущего окна удаляет план и не приостанавливает исправную комнату.
- Личная домашняя БД и основной VPS этим прогоном не менялись.

В базовом кандидате `3d1751f` обнаружен и исправлен в `43a1669` неверный формат
разрешённых ID комнат: они base64url, а не hex. Во время первого перехода пауза
старого кандидата проверялась непосредственно в его БД; следующие окна и проверки
снимков комнаты выполнены через HTTP на исправленной версии.

22 Linux contract tests покрывают также отказ по истечении окна, неудачный откат,
проверку архивов и сохранение текущей координации при восстановлении исторической
копии. Серверные тесты включают реальный отложенный HTTP-запрос; PostgreSQL CI,
Windows/Linux desktop regression, typecheck, сборка и сканирование секретов зелёные.

Уведомление проверено в Chrome на 1440, 390 и 1826 px: план, предупреждение за
5 минут, обслуживание, потеря связи и возврат сервера. Отсчёт доступен экранному
диктору без объявления каждого тика; действие восстановления проверено клавишей
Enter. Единственное замечание независимого дизайн-ревью исправлено. Fullscreen
capture проверяет портал в тестовом DOM-контейнере; реальный видеопоток и загрузка
desktop под обслуживанием этим прогоном не проверялись и остаются сквозной регрессией R6.

Для старого основного VPS нужен первый контролируемый переход в выбранное
владельцем окно: исходный кандидат не знает maintenance protocol 1. Текущие
аккаунты, секреты и БД должны сохраниться; перенос домашней личной БД не выполняется.
После этого применим штатный `schedule-update`. R3.4 не принята владельцем автоматически.
