## Дополнительная чистая установка

Использован официальный Ubuntu 24.04.5 amd64 WSL-образ; SHA-256 сверён с
опубликованным Ubuntu списком. До запуска отсутствовали Linux Docker, сокет
Docker и Compose; Windows Docker исключён из PATH. Установщик установил Docker
29.10.0 и Compose 5.8 через официальный APT-репозиторий, включил systemd-службу
Docker и поднял приложение с PostgreSQL. Readiness успешен.

Первоначально DNS внутри этого одноразового WSL не разрешал registry; исправлена
только сеть тестового дистрибутива, затем установка завершилась. Это проверка
чистого Ubuntu userspace и установки зависимостей, а не проверка отдельного
VPS-ядра. Реальный VPS, публичный DNS и HTTPS проверены отдельно выше.

## R3.3 — резервное копирование и восстановление

Проверено на отдельной БД и отдельных контейнерах VPS; личная БД не затронута:

- Архив проверяется по manifest/SHA-256, права 0600, медиа не включаются.
- После создания копии добавлена комната; восстановление выбрало новую БД,
  сохранило исходную БД, вернуло исходную комнату без более поздней записи.
- Сохранены ID пользователя, действующая браузерная сессия, SESSION_SECRET и
  desktop-токен; авторизованный запрос устройства после восстановления успешен.
- Ежедневный systemd-таймер создан и остаётся выключенным.
- PostgreSQL backup-check сверяет данные UTF-8 и полную историю миграций;
  повторное восстановление в непустую БД отклоняется (#37).
- 15 Linux contract tests: повреждение архива, выход путей за каталог, ссылки,
  несовместимый образ, исключение медиа и возврат каталога при ошибке переключения.

Ограничения: офлайн-копия кратко останавливает пишущие сервисы и запрещена при
активном просмотре; восстановление требует тот же digest приложения. Локальная
копия не защищает от потери VPS. Старые БД и каталоги намеренно сохраняются;
их очистка выполняется отдельно после приёмки восстановления.
