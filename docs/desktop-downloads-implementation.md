# Desktop: локальная загрузка и просмотр — 0.4.0-rc.1

Дата: 2026-11-18. Серверный путь Sonarr/qBittorrent/TorrServer/Jellyfin сохранён.

## Реализованный сценарий

1. Привязать устройство к аккаунту и найти тайтл в desktop.
2. Найти раздачу через серверные индексаторы Prowlarr. Показаны размер, сиды и источник.
3. Получить список файлов, отметить нужные серии, проверить/исправить распознанные номера. Есть «Отметить все» и «Сбросить».
4. Скачать в выбранную папку устройства. До двух активных раздач; пауза, продолжение с проверкой частей, остановка без удаления файлов. После перезапуска продолжение явное.
5. Автоматически подготовить проверенные файлы по одному через FFmpeg. Загрузка остальных продолжается. Общий прогресс серии: 80% загрузка, 20% подготовка. Ошибка подготовки допускает повтор из библиотеки.
6. Разрешить тайтл комнате, открыть комнату, выбрать desktop в источнике плеера. Друг смотрит в браузере под своим аккаунтом, без установки desktop. Уже существующее разрешение тайтла распространяется на новые подготовленные серии.

## Устройство реализации

- `POST /api/desktop/releases`: поиск и получение torrent-метаданных по непрозрачному идентификатору, привязанному к устройству. Срок 30 минут; после перезапуска сервера поиск повторяется. Требуются token устройства и текущий protocol header.
- API-ключи и download URL Prowlarr остаются на сервере. Сервер не запускает скачивание медиаданных новым маршрутом. Размер metadata ограничен 8 МиБ.
- Desktop: WebTorrent 3.0.21, TCP, проверка torrent pieces, затем полная идентификация файла существующей библиотекой. Проверяются небезопасные пути, дубликаты, номера серий, доступное место и ссылки внутри каталога назначения.
- Торрент-движок запускается при начале/продолжении загрузки, а не при открытии приложения. UPnP/NAT-PMP, LAN discovery и web seeds отключены. Во время получения частей клиент также отдаёт их пирам. После получения выбранных файлов torrent закрывается.
- Состояние загрузок хранится отдельно от библиотеки; запись атомарная, операции сериализованы. Подготовленные копии используют прежний механизм разрешений, WebRTC, relay и смены хоста.
- Отмена и удаление записи не удаляют исходники. Удаление библиотечной записи сохраняет оригинал, удаляя управляемую подготовленную копию согласно существующей логике.

## Проверено

- Сервер: 538 тестов пройдены, 1 пропущен; TypeScript и production build успешны. Новые тесты: принадлежность/истечение поискового handle, отсутствие ключей в выдаче, частичная/полная ошибка индексаторов, ограничение origin download URL.
- Desktop: 10 тестов на Windows и в Linux builder. Реальный локальный BitTorrent: выбранные 1-я и 3-я серии, пауза/продолжение, побайтовая проверка результата, сохранение состояния; повторная подготовка после ошибки; изменённый исходник по-прежнему отвергается; существующие тесты транспорта и protocol mismatch.
- Сквозной ручной тест в изолированной среде: desktop → новый серверный API → синтетический индексатор → локальный TCP seed → две выбранные серии → реальный FFmpeg → библиотека → разрешённая комната → два браузерных аккаунта. Оба video элемента имели readyState=4 и paused=false, плеер показывал прямой канал. Это локальная проверка, не проверка сети друга через интернет.
- Упакованное Windows-приложение запустилось; N-API зависимость загрузилась. Обновление существующей изолированной установки прошло с exit code 0. Исходники и версия внутри Windows/Linux ASAR сверены с checkout.
- Linux: AppImage собран, runtime отвечает, упакованный node-datachannel загружается в Linux. Настоящий Arch GUI/keyring/обновление остаются отложенной пользователем приёмкой.
- UI проверен на 1265px и 390px, горизонтального переполнения нет. Для адаптивных снимков используется реальный renderer с синтетическим IPC, а не имитация торрент-проверки. Native-снимки после упаковки перекрывал запрос Windows Security; системные разрешения не менялись.
- Impeccable: независимый ревью выявил скрытую выше экрана ошибку старта. Исправлено локальное сообщение у кнопки и проверка пустого выбора; повторный verdict — `ship` для этого исправления. Существующие DESIGN.md/PRODUCT.md сохранены; Inter оставлен как часть принятой системы, контраст акцентных кнопок улучшен.

## Известные границы

- Поддерживаются torrent-файлы, возвращаемые Prowlarr напрямую. Magnet-only и redirect-ответы не поддерживаются; такие раздачи потребуют другого источника или ручного подключения скачанного файла.
- Распознавание эпизодов по именам эвристическое: сезон/абсолютная нумерация/спецвыпуски требуют проверки пользователем. Отдельная модель сезонов/дорожек в этом изменении не вводилась.
- При выборе отдельных файлов BitTorrent может получить граничные части соседних файлов; невыбранные серии не импортируются в библиотеку.
- Проверка свободного места до старта учитывает выбранные исходники и резерв 256 МиБ, но не гарантирует место для всех будущих MP4-копий. Диск может заполниться во время работы; ошибка отображается, файлы сохраняются.
- Подготовка сохраняет существующие ограничения выбора аудио/субтитров. Обработка не является воспроизведением недокачанного файла.
- Пакеты неподписанные, обновление вручную. Установленный desktop требует HTTPS. VPN для недоступного индексатора нужен на сервере; доступность пиров и трекеров зависит от сети desktop.
- Общий сервер по-прежнему нужен для пользователей, координации и резервного relay. Доступ из внешней сети и настоящий Arch в этой итерации не подтверждены.
