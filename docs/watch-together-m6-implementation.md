# М6 — передача desktop → браузер

Версия desktop: 0.2.0-alpha.1. Дата: 2026-11-17.

## Реализованный сценарий

1. Хост привязывает устройство, подключает файл к тайтлу и серии, готовит MP4 и разрешает раздачу этому тайтлу в выбранную комнату.
2. Участники входят в аккаунты и подключаются к просмотру комнаты. Участник с правом управления выбирает устройство в панели «Источник комнаты» рядом с плеером.
3. Браузер получает подготовленный файл напрямую по WebRTC DataChannel. Если прямой маршрут недоступен, диапазоны файла ретранслируются через центральный сервер. Устанавливать desktop зрителю не требуется.
4. Сохраняются существующий плеер, перемотка, полноэкранный режим, команды комнаты и учёт фактически просмотренных участков. Выбранный хост общий для комнаты и сохраняется при переходах; следующая серия должна быть подготовлена и разрешена на этом устройстве.
5. Возврат к серверной библиотеке — явное действие. Отзыв доступа, изменение файла и недоступный источник не подменяются молча другой версией серии. После восстановления можно повторить подключение.

## Транспорт и ограничения

- Подготовленный faststart MP4, H.264/AAC; первая звуковая дорожка. Переключение дорожек, передача отдельных субтитров и серверный OCR кадра для desktop-файла пока не реализованы; интерфейс это объясняет. Серверный источник сохраняет прежние возможности.
- Service worker перехватывает только `/desktop-media/<lease>/file.mp4`. Он не кэширует медиа и не заменяет оболочку приложения. Диапазоны по 1 МиБ передаются из вкладки через MessageChannel; RTC-пакеты — по 16 КиБ. Без service worker остаётся обычный HTTP Range через сервер.
- Это передача байтов исходной подготовленной версии, не захват экрана и не повторное кодирование при просмотре. Выбор сделан для сохранения перемотки и обычного MP4-плеера. Полноценное сравнение затрат с live WebRTC/HLS на разных сетях ещё не проведено.
- Сервер хранит выбор устройства в БД, а сигнальные подключения и очередь ретрансляции — в памяти одного процесса, как текущий координатор комнат. Несколько независимых серверных процессов без общего координатора не поддержаны. Перезапуск сервера требует переподключения; автономной комнаты без него нет.
- `DESKTOP_STUN_URLS`: необязательный список STUN-адресов через запятую. По умолчанию пуст: внешние STUN-сервисы скрыто не используются. В разных сетях без настроенного STUN вероятна ретрансляция. TURN не настроен.
- `DESKTOP_RELAY_ENABLED=0` отключает резервную ретрансляцию. По умолчанию включена. Она расходует исходящий трафик сервера и хоста, хотя медиа не сохраняется на серверном диске. Плеер показывает фактический маршрут и объём переданных данных.
- Ограничения: 8 подключений на устройство, 64 суммарно; 32 ожидающих блока на сервер и 4 на подключение; 256 МиБ/мин на зрителя через relay; ожидание блока 15 секунд; неактивное подключение истекает через 90 секунд. Это защитные пределы alpha, не гарантия пропускной способности.
- Автоматический переход на другое устройство при обрыве относится к М7 и здесь не реализован.

## Доступ

Проверяются аккаунт, членство в группе, подключение к просмотру, разрешение владельца «тайтл × комната», выбранный хост, текущая серия и полная SHA-256 подготовленного файла. Идентификатор подключения принадлежит одному зрителю. Произвольные пути, токен устройства и файловая система не доступны удалённой странице.

Хост опрашивает задания и разрешения каждые 250 мс; локальное разрешение без обновления живёт не больше 3 секунд. Перед чтением проверяются размер и время изменения исходника и подготовленного файла. Отзыв прекращает выдачу новых диапазонов; уже полученный зрителем буфер отозвать невозможно.

## Проверки и границы приёмки

- 50 серверных тестов: desktop, транспорт, права комнаты, планирование, переходы сеанса, история и покрытие просмотра — успешно.
- 7 desktop-тестов на Windows и Linux, включая реальный FFmpeg и чтение разрешённых диапазонов — успешно.
- TypeScript и production-сборка Next.js — успешно.
- Изолированный стенд с двумя синтетическими аккаунтами, без использования личных медиаданных. Тестовый ролик: 1920×1080, 60 секунд, 30 858 537 байт, H.264/AAC.
- В браузере наблюдались воспроизведение напрямую с Windows-хоста и принудительная ретрансляция (`relay=1`), перемотка и команды общей комнаты. Счётчики маршрута подтверждают фактическую передачу, а не только установленное соединение.
- В контрольном замере при одновременном воспроизведении: 52,677 и 52,224 секунды, разница около 0,45 секунды. Это единичное локальное наблюдение, не гарантия задержки. После повторных перемоток прямой маршрут передал 64,1 МиБ при 0,0 МиБ через relay. Повторные диапазоны учитываются в трафике повторно.
- Закрытие Windows-хоста показало потерю связи и офлайн-устройство; после исчерпания буфера комната перешла в ожидание. Перезапуск хоста сохранил привязку; явное переподключение восстановило поток. Автосмена устройства не проверялась и не реализована.
- Исправлена синхронизация зрителя, уже достигшего конца серии, при общей перемотке назад. Для браузерной блокировки autoplay остаётся первый пользовательский жест: зритель без права управления может разрешить локальное воспроизведение уже играющей комнаты, не посылая общую команду.
- Обнаружено и исправлено ожидание пяти секунд буфера: native MP4 на паузе может остановить загрузку раньше. Для desktop готовность определяется стандартным readyState браузера, чтобы не удерживать комнату в бесконечном ожидании.
- `https://pivocinema.duckdns.org/` не ответил из среды проверки за 20 секунд. Это не доказывает недоступность для всех, но сквозная приёмка между независимыми сетями через публичный HTTPS пока не выполнена.
- Нативная проверка GUI на Arch, мобильном Safari/Android и телевизоре остаётся открытой. Сборка AppImage сама по себе её не заменяет.

М6 считается локально проверенной alpha-реализацией, а не завершённой сетевой приёмкой. Для последней нужны два независимых подключения, доступный HTTPS, проверка прямого/резервного маршрутов, длинной серии, перемотки, обрыва и повторного подключения.

Собраны NSIS и AppImage; наличие transport и stream-provider проверено внутри обоих app.asar. Linux-сборка использовала ранее проверенный образ M5 с теми же закреплёнными версиями зависимостей после зависшей повторной загрузки Electron; исходники и тесты заменены на M6. Предупреждение упаковщика о Linux desktopName/ассоциации окна остаётся известным ограничением интеграции с рабочим столом, не результатом проверки Arch GUI. SHA-256 лежат в `apps/desktop/release/SHA256SUMS-0.2.0-alpha.1.txt`.

PostgreSQL-миграция `1795021200000_desktop-streams` применена, контейнер healthy, service worker отвечает HTTP 200. Предыдущий образ сохранён как `home-theater/anime-calendar:m5-before-m6-20261117`.

Миграция добавляет только `desktop_room_sources`; существующие данные и медиабэкенд остаются. Установщик Windows обновляется поверх предыдущего после закрытия хоста; на Arch заменяется AppImage. Пакеты неподписанные, автообновлений нет. Для отката просмотра выберите серверный источник; для отката сервиса используйте предыдущий образ. Существующий desktop M5 не объявляется способным передавать видео: нужны метаданные подготовленной версии из нового клиента.
