# Разработка и выпуск

## Задача → PR → приёмка

Работа начинается с согласованного Issue: результат, критерии, зависимости,
необходимые проверки. Одна задача может иметь несколько небольших PR.
Ветки `codex/*` от актуального main, слияние через PR после CI и ревью.
Второе человеческое одобрение каждого PR не требуется. Стабильная публикация и
обновление боевого сервера требуют решения владельца. Main может содержать ещё
не принятые владельцем изменения; постоянной develop нет.

Project: Запланировано → Готово к работе → В работе → На проверке → Принято.
Слияние PR переводит работу на проверку, не закрывает продуктовую задачу.
Не использовать `Closes #...` до приёмки. Блокировка отмечается отдельно с причиной.
После работы агент прикладывает commit/build, результаты проверок и непроверенные
сценарии. Для временного feature flag сразу нужна задача удаления.

## CI

Обязательный итоговый статус — **CI gate**. Он проверяет результаты всех выбранных
работ, включая ошибки и отмену. Документационный PR пропускает сборки, но не скан
секретов. Неизвестные и общие файлы запускают все проверки. Workflow-файлы также
запускают весь набор. Только изменение фильтров не должно позволять пропустить
проверку затронутого компонента; это часть ревью CI.

- Сервер: npm ci, typecheck, Vitest, Next production build.
- БД/API/server: PostgreSQL 17, миграции, SQL, импорт и тесты.
- Desktop: frozen pnpm lockfile, явно выбранные native install scripts, тесты
  Windows и Linux. Это не проверка GUI или полноценных установщиков.
- Gitleaks: полная достижимая история, маскированный вывод. Исключения только
  узкие, проверенные ложные срабатывания; не исключать целиком тесты/документацию.
- Отчёты 14 дней. Временные пакеты 7 дней; публикации Releases не чистятся
  автоматически. Кандидаты/упаковка на явном запуске, стабильный выпуск отдельно.

Внешние PR требуют одобрения запуска, не получают секретов и прав публикации.
Тесты не используют production БД/ключи. Actions закреплены по SHA. Dependabot
создаёт PR, но не получает безусловного разрешения на слияние.

## Артефакты и эксплуатация

Desktop публикуется в Releases, сервер — GHCR. Версии продукта общие; точный
коммит и digest образов фиксируются в выпуске. Пересобранный пакет проверяется
повторно. Реализация автоматической публикации кандидатов/обновлений входит в
этапы подготовки дистрибуции; наличие CI не объявляет этот путь готовым.

Тестовая установка имеет отдельные БД, секреты, каталоги и порты. GitHub не
получает SSH-доступ к VPS. Подробные принятые правила — в плане 1.0.
